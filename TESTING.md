## Bugs

I have encountered several bugs during the development of this project, but I have been able to fix them all. Here are some of the bugs I encountered:

- Checkout total always showed €0 and Stripe rejected payment:
    - The checkout view attempted to read cart data from the session, however, the project uses a database‑backed cart (Cart and CartItem models), not a session cart.
    - I fixed this by updating the checkout view to read cart data from the database instead of the session.

- After completing a payment, the checkout success page loaded but immediately raised a NoReverseMatch error. The template attempted to generate a link back to the products page using {% url 'products' %}, but Django could not find any URL pattern with that name.
    - The products app does not define a URL pattern named "products". Django’s {% url %} tag only works with the name assigned in urls.py, not the app name or folder name.
    - I updated the link in checkout_success.html to use the correct URL name defined in products/urls.py

- Error 500 when deleting a user profile due to protected Order relations
    - Attempting to delete a user profile caused a server error (HTTP 500). The deletion failed whenever the user had previously placed an order. Instead of removing the profile, Django raised an exception and the application crashed.
    -The Order model used on_delete=models.PROTECT on its foreign key to the user. This prevented the user from being deleted if any related orders existed. Since the project does not require historical order preservation for deleted users, the protective constraint caused unnecessary failures.
    - Updated the Order model to use: on_delete=models.CASCADE This allows Django to automatically delete all related orders when a user profile is removed. After updating the model, new migrations were created and applied.

### Known Issues

When a User deletes their profile, all of their orders are also deleted due to the on_delete=models.CASCADE setting on the Order model. This means that if a user deletes their profile, they will lose access to their order history. This is not ideal, but it is a trade‑off that I have made in order to allow users to delete their profiles without encountering errors and I plan to fix this in a future update by implementing a soft delete mechanism for user profiles, which would allow users to deactivate their accounts without permanently deleting their order history.

> There are no remaining bugs that I am aware of, though, even after thorough testing, I cannot rule out the possibility.
